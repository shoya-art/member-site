# 作業設計書：受講者アクション → LINE 通知

このドキュメントは **コーディング初心者向け** に、次の2つに分けて書いています。

- **A. コード・設定ファイルとして倉庫に入れたもの**（こちらで用意済み）
- **B. あなた（ジローさん）が Supabase / LINE の画面上で行う作業**（手を動かす必要があるもの）

---

## 1. 何を作るか（ゴール）

受講者が次のどれかをしたとき **あなたの LINE に通知が1通届く** ようにします。

| イベント | サイト上の操作 | データベースのテーブル |
|----------|----------------|------------------------|
| 講義完了 | 講義モーダルで「視聴完了 ✓」 | `lecture_views`（**初回のみ** INSERT のとき通知） |
| ワーク完了 | 「ワークを提出する」または「回答を更新する」 | `work_answers`（提出・更新のたびに通知） |
| 日報（チェックイン） | チェックイン画面で登録（初回） | `checkins`（**初回 INSERT のみ**通知。同日の「更新」は既定では通知しない※） |

※同日のチェックインを更新したときも通知したい場合は、後述の **シークレット `CHECKIN_NOTIFY_ON_UPDATE=true`** を Supabase に追加します。

---

## 2. 仕組みのイメージ（全体像）

```
[会員サイト GitHub Pages]
        │
        │ ログイン済みのブラウザから
        ▼
[Supabase データベース]
   lecture_views / work_answers / checkins に保存
        │
        │ 「行が追加・更新された」ことを検知
        ▼
[Database Webhook]  ← あなたが Supabase 画面で3つ登録する
        │
        │ HTTPS POST（秘密の合言葉つき）
        ▼
[Edge Function: notify-instructor]  ← このリポジトリのコードをデプロイする
        │
        │ LINE Messaging API
        ▼
[あなたの LINE]
```

ポイント：

- **GitHub Pages だけでは LINE に送れません**（秘密鍵を置けないため）。
- その代わり **Supabase 上の小さなプログラム（Edge Function）** が LINE に代わって送ります。
- 「誰がやったか」は **会員の user_id** から `profiles` または Auth のメールを調べて、通知文に入れます。

## 4. B. あなたがやること（チェックリスト）

上から順に進めるとスムーズです。

### 4-1. LINE Developers（Messaging API）

1. [LINE Developers コンソール](https://developers.line.biz/) にログインする。
2. **プロバイダー** と **Messaging API 用のチャネル**（LINE 公式アカウント）を用意する（既にあるならそれを使う）。
3. チャネルの **「Messaging API」** タブで次を確認・取得する。
   - **チャネルアクセストークン（長期）** を発行する。
4. スマホの LINE で、その **公式アカウントを友だち追加**する（あなた自身の LINE）。
5. **あなたの LINE ユーザー ID** を取得する（通知の宛先）。  
   代表的な方法：
   - 開発用に **Webhook 受信** で `userId` をログに出す、または
   - LINE が案内する **Webhook 検証用のツール / ボットに自分でメッセージを送ってイベント JSON を確認** する  
   詳しい手順は [Messaging API のドキュメント](https://developers.line.biz/ja/docs/messaging-api/) の「友だち追加」「Webhook」を参照してください。  
   **取得した `U` から始まるユーザー ID** をメモしておきます（後で `LINE_TO_USER_ID` に貼ります）。

> 注意：無料プランなど **月あたりの無料メッセージ通数に上限** がある場合があります。公式の料金・上限を確認してください。

### 4-2. Supabase CLI（パソコンに一度だけ入れる）

Edge Function をアップロードするために、Supabase の CLI ツールを使います。

1. 公式の手順に従い **Supabase CLI をインストール**する。  
   参考：[Supabase CLI](https://supabase.com/docs/guides/cli)
2. ターミナルでこのリポジトリのルートに移動する（`lectures.html` があるフォルダ）。
3. ログインとプロジェクト紐付け（初回のみ）：

```bash
supabase login
supabase link --project-ref ejcajjtptbrcwmgzqhjz
```

`project-ref` は、会員サイトの JS に出ている URL  
`https://ejcajjtptbrcwmgzqhjz.supabase.co` の **`ejcajjtptbrcwmgzqhjz`** 部分です。

### 4-3. シークレット（秘密情報）を Supabase に登録

Supabase ダッシュボード → **Project Settings** → **Edge Functions** → **Secrets**（または CLI）で、次の名前を **必ず** 設定します。

| 名前 | 中身 |
|------|------|
| `WEBHOOK_SECRET` | **自分で考えた長いランダムな文字列**（例：20文字以上の英数字）。Database Webhook のヘッダに同じ値を入れます。 |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE の **チャネルアクセストークン（長期）** |
| `LINE_TO_USER_ID` | あなたの **LINE ユーザー ID**（`U` から始まる） |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase の **service_role** キー（Project Settings → API。**絶対にフロントに書かない**） |

CLI の例（値はあなたのものに置き換え）：

```bash
supabase secrets set WEBHOOK_SECRET='ここに長いランダム'
supabase secrets set LINE_CHANNEL_ACCESS_TOKEN='ここにLINEトークン'
supabase secrets set LINE_TO_USER_ID='Uxxxxxxxx'
supabase secrets set SUPABASE_SERVICE_ROLE_KEY='ここにservice_roleキー'
```

※ `SUPABASE_URL` は Edge Function 実行時に Supabase 側で自動注入されることが多いですが、もしエラーになる場合は同じ Secrets に `SUPABASE_URL=https://ejcajjtptbrcwmgzqhjz.supabase.co` も追加してください。

任意：

| 名前 | 中身 |
|------|------|
| `CHECKIN_NOTIFY_ON_UPDATE` | `true` にすると、チェックインの **更新（UPDATE）** でも LINE 通知する |

### 4-4. Edge Function のデプロイ

リポジトリルートで：

```bash
supabase functions deploy notify-instructor
```

成功すると、次のような URLで呼び出せます（例）：

`https://ejcajjtptbrcwmgzqhjz.supabase.co/functions/v1/notify-instructor`

### 4-5. Database Webhook を 3 本登録する

Supabase ダッシュボード → **Database** → **Webhooks** → **Create a new hook**。

共通設定（各 Webhook で同じにする）：

- **Type of webhook**：`HTTP Request` など、HTTPS POST できるもの
- **URL**：`https://ejcajjtptbrcwmgzqhjz.supabase.co/functions/v1/notify-instructor`
- **HTTP Headers** に1行追加：
  - Name: `x-webhook-secret`
  - Value: `4-3` で設定した **`WEBHOOK_SECRET` と同じ文字列**

以下 **3 つのフック** を作ります。

#### フック 1：`lecture_views`

- **Table**：`lecture_views`
- **Events**：`INSERT` のみにチェック（UPDATE は付けない）

#### フック 2：`work_answers`

- **Table**：`work_answers`
- **Events**：`INSERT` と `UPDATE` にチェック

#### フック 3：`checkins`

- **Table**：`checkins`
- **Events**：`INSERT` のみ（同日の更新も通知したいなら `UPDATE` も ON にし、かつ `CHECKIN_NOTIFY_ON_UPDATE=true` を設定）

> もし画面に **「HTTP Request」のテンプレート** があり、**「Supabase Edge Functions」向けのプリセット** があれば、それを選ぶと URL が自動補完される場合があります。その場合も **`x-webhook-secret` ヘッダは手動で足してください**（この Function はヘッダで合言葉を検証しています）。

### 4-6. 動作確認

1. **テスト用の会員アカウント**でサイトにログインする。
2. 講義を1つ開き「視聴完了 ✓」→ LINE に「講義を視聴完了」系の文面が届くか確認。
3. ワークを提出 → 「ワークを提出しました」が届くか確認。
4. チェックインを登録 → 「日報（チェックイン）を登録しました」が届くか確認。

届かない場合：

- Supabase → **Edge Functions** → **Logs** で `notify-instructor` のエラーログを確認。
- LINE のトークン・ユーザー ID が正しいか再確認。
- Webhook の URL / `x-webhook-secret` が Function と一致しているか確認。

## 5. 通知文の例

- `【リリー】講義を視聴完了しました` + 会員のメール（または名前）+ `講義ID: 3-2`
- `【リリー】ワークを提出しました` + 会員 + `講義ID: 4-3`
- `【リリー】日報（チェックイン）を登録しました` + 会員 + 日付 + 数値3つ

講義の **日本語タイトル** は本文に含めていません（データがフロントの JS にしかないため）。必要なら、後から `lecture_id` とタイトルの対応表を別途作るか、DB にマスタテーブルを足す拡張が可能です。

---

## 6. セキュリティの注意

- **service_role キー** と **LINE チャネルアクセストークン** は、**GitHub にコミットしない**でください（Supabase の Secrets にだけ置く）。
- `WEBHOOK_SECRET` を推測されにくい長さにしてください。
- 受講者に「提出やチェックインの内容が講師側に通知される」旨を、利用案内や規約に書いておくとトラブル防止になります。

## 7. 用語ミニ辞典

| 用語 | ひとことで |
|------|------------|
| Edge Function | Supabase のサーバー上で動く小さなプログラム |
| Database Webhook | テーブルに行が追加・更新されたとき、指定 URL に自動で POST する仕組み |
| Messaging API | LINE 公式が提供する「ボットからユーザーへメッセージを送る」API |
| project-ref | Supabase プロジェクトの識別子（URL の一部） |

---

以上です。デプロイや Webhook で詰まったら、**エラー画面のスクリーンショット** と **Edge Functions のログ** を控えて質問すると解決が早いです。
